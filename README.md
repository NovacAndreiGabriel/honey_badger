## Overview

Honey Badger is a chess engine written in C23. Its search is inspired by
[Stockfish](https://github.com/official-stockfish/Stockfish), and its evaluation is a small NNUE
network trained on 80 million positions.

It speaks the [UCI protocol](https://backscattering.de/chess/uci/), so it works with any chess GUI
(Cute Chess, Arena, En Croissant, ...) and with testing tools such as
[fastchess](https://github.com/Disservin/fastchess) and cutechess-cli.

It also plays on Lichess as [**HoneyBadgerChessBot**](https://lichess.org/@/HoneyBadgerChessBot).

## Features

**Board and move generation**
- Bitboards with magic bitboards for sliding pieces
- Legal move generation with lazy legality checks, verified with perft (6 standard positions)
- Incremental Zobrist keys, pawn keys, and repetition tracking per ply

**Evaluation**
- NNUE: 768 inputs (piece × square, both perspectives) → 256 hidden neurons (SCReLU) → 1 output
- Incremental, lazily updated accumulators, as in Stockfish
- SIMD with fallbacks: AVX2, SSE2, NEON and portable C, selected at compile time
- Quantized integer inference, verified bit-exact against the Python training model

**Search**
- Principal variation search with iterative deepening and aspiration windows
- Quiescence search
- Transposition table ("search cache"): 3-entry 32-byte clusters, aging, large/huge pages
  on Windows and Linux
- Staged move picker with static exchange evaluation (SEE)
- History tables: butterfly, low-ply, capture, pawn and continuation histories; pawn correction history
- Pruning and reductions: null move pruning with verification, late move reductions, futility pruning,
  razoring, ProbCut, SEE pruning, singular / multi-cut / negative extensions, internal iterative reductions
- Mate distance pruning, draw detection (50-move rule, repetitions)

**Engine**
- Lazy SMP multithreading with thread voting
- Time management based on Stockfish's, with extra caps per move
- Pondering, MultiPV

## Building

Requirements: GCC (or Clang) with C23 support and GNU Make.

```sh
make build-release     # build/release/honey_badger(.exe)
make build-debug       # build/debug/honey_badger(.exe)
make run-release ARGS=test
make clean
```

The release build uses `-march=native`, so the binary is tuned for (and may only run on) the CPU it
was built on. To build for other machines with AVX2, replace `-march=native` with `-mavx2` in the
`Makefile`.

**Windows:** install [MSYS2](https://www.msys2.org/) and the UCRT64 toolchain:

```sh
pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-make
```

Then run `make` from the UCRT64 terminal, or `mingw32-make` from PowerShell / cmd.

On startup the engine prints which NNUE code path it was compiled with, e.g.
`Honey Badger (NNUE: AVX2)`.

## Usage

Run the executable without arguments to start in UCI mode, then add it to your GUI as a UCI engine.

| Command line | Action |
|---|---|
| `honey_badger` | UCI mode |
| `honey_badger test` | run the test suite (NNUE, perft, search cache, SEE, histories, move picker, search) |
| `honey_badger bench [depth]` | fixed-depth search over 16 positions; the node count is the build's signature |

### UCI options

| Option | Default | Range | Description |
|---|---|---|---|
| `Threads` | 1 | 1–1024 | search threads |
| `Hash` | 16 | 1–65536 | transposition table size in MB |
| `Clear Hash` | | | clear the transposition table |
| `Ponder` | false | | think on the opponent's time |
| `MultiPV` | 1 | 1–256 | number of principal variations to report |
| `Move Overhead` | 10 | 0–5000 | time in ms reserved per move for communication delays |

### Extra commands

| Command | Action |
|---|---|
| `d` | show the board and FEN |
| `eval` | static NNUE evaluation of the current position |
| `go perft <depth>` | move counts per root move |
| `bench [depth]` | run the bench from UCI mode |

## NNUE training

The network was trained in PyTorch on 80 million labeled positions:
768 → 256 (SCReLU) → 1, SmoothL1 loss, quantized with QA = 255 and QB = 64.
The export script writes the quantized weights to `src/nnue_weights.c`.
